## Goal

Let a skill effect apply knockback (push a target away from a point, over a fixed duration, at a rate per second) to `Player` and `Enemy`, when today the only cross-component contract (`IDamageable`) can only deal damage.

## Context

- Orientation: `docs/architecture/orientation/index.md`
- Relevant subfiles: `modules.md` (Characters, Gameplay, Skill System sections), `paradigm.md` (interface-driven contracts rule)
- Related inbox request: `docs/architecture/architect-inbox/c2.md`
- Related task: `docs/architecture/tasks/1.md` (Skill System generalization this builds on)

Blocker (from coder-role): no contract exposes displacement/force to a skill effect (only `IDamageable.TakeDamage`), and `PlayerMover`/`EnemyMover` drive movement so differently (`Rigidbody2D.velocity` every `FixedUpdate` vs. direct `transform.position` coroutine) that an external push would be overwritten or would fight the mover's own movement within a frame.

## Inputs

- Files read: `Assets/Scripts/Characters/IDamageable.cs`, `IReplenishable.cs`, `Assets/Scripts/Gameplay/Mover.cs`, `Assets/Scripts/Characters/Player/PlayerMover.cs`, `Assets/Scripts/Characters/Enemy/EnemyMover.cs`, `Assets/Scripts/Gameplay/Skill System/ExecutorData.cs`, `AuraAreaDetector.cs`, `Assets/Scripts/Gameplay/Health System/Health.cs`, `Assets/Scripts/Characters/Player/Player.cs`, `Assets/Scripts/Characters/Enemy/Enemy.cs`

## Options considered

### Option A — `IKnockbackable` + `Mover.IsOverridden` flag (chosen)
- Pros: smallest change; matches project's composition/interface-contract convention; reuses `AuraAreaDetector.FindTargetsInRadius`'s existing `List<IDamageable>` return type as-is (effect casts `target is IKnockbackable`); each mover keeps its own physics model.
- Cons: `Mover` gains a second abstract method; does not fix the underlying two-physics-models split (Rigidbody2D velocity vs. transform.position coroutine), only makes both movers cede control safely during an external push.

### Option B — Unify movers on Rigidbody2D physics first
- Pros: permanently resolves the "two incompatible physics models" hotspot for any future external-force mechanic, not just knockback.
- Cons: much bigger, riskier change — rewrites `EnemyMover`'s core movement model, touches `EnemyStateMachine` behavior built around instant `transform.position` sets, no test safety net, well beyond this request's scope.

### Chosen
"A: IKnockbackable + Mover.IsOverridden flag (Recommended)" — user selected via AskUserQuestion, 2026-09-24.

## Decision summary

Add a new `IKnockbackable` interface (`Characters/`, alongside `IDamageable`/`IReplenishable`) with `ApplyKnockback(Vector2 direction, float speedPerSecond, float durationInSeconds)`, implemented by `Player` and `Enemy`, each delegating to its own `Mover`. `Mover` (abstract base) gains a `protected bool IsOverridden { get; set; }` flag and an abstract `ApplyKnockback(...)` method; `PlayerMover.Move`/`EnemyMover.Move` become no-ops while `IsOverridden` is true, so the state machine's per-frame `Move` calls stop fighting an active knockback. Each mover implements `ApplyKnockback` using its own existing physics model (Rigidbody2D velocity for `PlayerMover`, a `transform.position` lerp coroutine for `EnemyMover`, replacing/canceling any in-flight `MoveTo`). No change needed to `AuraAreaDetector`/`IDamageable` — a skill effect that already holds an `IDamageable` target can test `target is IKnockbackable` and call it directly. The actual knockback skill effect (mouse-point area resolution, max-range clamp, `ISkillEffect` implementation) is left to coder-role — not architecturally blocked per the inbox note.

2. Edit `Assets/Scripts/Gameplay/Mover.cs`: add `protected bool IsOverridden { get; set; }` and `public abstract void ApplyKnockback(Vector2 direction, float speedPerSecond, float durationInSeconds);`.
3. Edit `Assets/Scripts/Characters/Player/PlayerMover.cs`: guard `Move` with `if (IsOverridden) return;`; implement `ApplyKnockback` via a coroutine that sets `IsOverridden = true`, drives `Rigidbody.velocity` for the duration, then restores `IsOverridden = false`.
4. Edit `Assets/Scripts/Characters/Enemy/EnemyMover.cs`: guard `Move` with `if (IsOverridden) return;`; implement `ApplyKnockback` via a coroutine (canceling any active `_moveCoroutine`) that sets `IsOverridden = true`, lerps `transform.position` along `direction` at `speedPerSecond` for `durationInSeconds`, then restores `IsOverridden = false`.
5. Edit `Assets/Scripts/Characters/Player/Player.cs`: implement `IKnockbackable`; promote the local `Mover mover` in `Awake` to a private field `_mover`; delegate `ApplyKnockback` to it.
